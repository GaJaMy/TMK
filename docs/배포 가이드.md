# 배포 가이드

## Production 배포 흐름

- `main` 브랜치에 push가 발생하면 GitHub Actions가 실행됩니다.
- 워크플로우는 테스트 후 `api`, `batch` 타깃 이미지를 Docker Hub에 push 합니다.
- 이후 운영 서버에 `docker-compose.prod.yml`을 업로드합니다.
- 서버에서 개별 GitHub Secrets를 조합해 `.env.prod` 파일을 생성합니다.
- `tmk-api`, `tmk-batch` 컨테이너를 내린 뒤 새 이미지를 pull 하고 다시 기동합니다.
- 현재 이미지는 단일 Docker Hub 리포지토리 `${DOCKERHUB_USERNAME}/tmk`에 `api`, `batch` 태그로 관리합니다.

## 필요한 GitHub Secrets

- `DOCKERHUB_USERNAME`
- `DOCKERHUB_TOKEN`
- `VULTR_HOST`
- `VULTR_USER`
- `VULTR_SSH_KEY`
- `PROD_DEPLOY_PATH`
- `PROD_POSTGRES_DB`
- `PROD_POSTGRES_USER`
- `PROD_POSTGRES_PASSWORD`
- `PROD_POSTGRES_PORT`
- `PROD_REDIS_HOST`
- `PROD_REDIS_PORT`
- `PROD_DOCUMENT_STORAGE_DIR`
- `PROD_ADMIN_JWT_SECRET`
- `PROD_USER_JWT_SECRET`
- `PROD_OPENAI_API_KEY`
- `PROD_OPENAI_EMBEDDING_MODEL`
- `PROD_OPENAI_CHAT_MODEL`
- `PROD_OPENAI_CHAT_TEMPERATURE`
- `PROD_OPENAI_CHAT_MAX_TOKENS`

개별 secret 을 조합해서 배포 시점에 `.env.prod` 파일을 생성하므로, 멀티라인 `.env` 전체를 secret 하나로 관리하지 않습니다.

## 서버 준비

- Vultr 인스턴스에 Docker와 Docker Compose Plugin이 설치되어 있어야 합니다.
- `PROD_DEPLOY_PATH` 예시: `/home/deploy/tmk`
- 최초 1회는 배포 계정이 `docker` 명령을 실행할 수 있어야 합니다.
