# 배포 가이드

## Staging 배포 흐름

- `staging` 브랜치에 push가 발생하면 GitHub Actions가 실행됩니다.
- 워크플로우는 테스트 후 `tmk-api`, `tmk-batch` 이미지를 Docker Hub에 push 합니다.
- 이후 Vultr 서버에 `docker-compose.staging.yml`을 업로드합니다.
- 서버에서 개별 GitHub Secrets를 조합해 `.env.staging` 파일을 생성한 뒤 `docker compose pull`과 `up -d`를 실행합니다.
- API 이미지는 `${DOCKERHUB_USERNAME}/tmk-api:${API_IMAGE_TAG}`, 배치 이미지는 `${DOCKERHUB_USERNAME}/tmk-batch:${BATCH_IMAGE_TAG}` 를 사용합니다.

## Production 배포 흐름

- `main` 브랜치에 push가 발생하면 GitHub Actions가 실행됩니다.
- 워크플로우는 테스트 후 `tmk-api`, `tmk-batch` 이미지를 Docker Hub에 push 합니다.
- 이후 운영 서버에 `docker-compose.prod.yml`과 `docker/postgres/init.sql`을 업로드합니다.
- 서버에서 개별 GitHub Secrets를 조합해 `.env.prod` 파일을 생성한 뒤 `docker compose pull`과 `up -d`를 실행합니다.
- API 이미지는 `${DOCKERHUB_NAMESPACE}/tmk-api:${IMAGE_TAG}`, 배치 이미지는 `${DOCKERHUB_NAMESPACE}/tmk-batch:${IMAGE_TAG}` 를 사용합니다.

## Staging 변수 이름

- `POSTGRES_DB`
- `POSTGRES_USER`
- `POSTGRES_PASSWORD`
- `POSTGRES_PORT`
- `REDIS_HOST`
- `REDIS_PORT`
- `DOCUMENT_STORAGE_DIR`
- `ADMIN_JWT_SECRET`
- `USER_JWT_SECRET`
- `OPENAI_API_KEY`
- `OPENAI_EMBEDDING_MODEL`
- `OPENAI_CHAT_MODEL`
- `OPENAI_CHAT_TEMPERATURE`
- `OPENAI_CHAT_MAX_TOKENS`

staging은 `API_IMAGE_TAG`, `BATCH_IMAGE_TAG`를 사용하고, production은 `IMAGE_TAG`를 워크플로우가 현재 커밋 SHA로 주입합니다.

## 서버 준비

- Vultr 인스턴스에 Docker와 Docker Compose Plugin이 설치되어 있어야 합니다.
- `STAGING_DEPLOY_PATH` 예시: `/home/deploy/tmk`
- 최초 1회는 배포 계정이 `docker` 명령을 실행할 수 있어야 합니다.
