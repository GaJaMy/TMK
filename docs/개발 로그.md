# TMK 개발 로그

> 목적: 커밋 단위 또는 작업 단위로 무엇을 수정했고 무엇을 개발했는지 기록한다.
> 원칙: 해당 시점에 실제로 반영된 작업만 기록한다.

---

## 2026-04-28

### 요구사항 및 설계 문서 재정리

- 사용자 인증, 관리자 기능, 문서 업로드, 시험 흐름 요구사항을 현재 서비스 방향에 맞게 다시 정리했다.
- ERD, DDL, 도메인 모델, API 명세를 새 구조 기준으로 다시 맞췄다.
- API 버전 관리를 `ApiVersion` 상수 방식으로 가져가는 규칙과 관련 문서를 추가했다.

### 관리자 웹 / 사용자 웹 프로토타입 정리

- 관리자 웹 로그인, 모니터링, 공용문제 관리, 관리자 관리 화면을 현재 요구사항에 맞게 정리했다.
- 사용자 웹 랜딩, 로그인, 문서 등록, 시험 보기, 시험 진행, 시험 내역 화면을 정적 프로토타입으로 구성했다.
- 기존 정적 리소스 흐름 대신 새 웹 화면 기준으로 문서와 화면 구성을 정리했다.

### 코어 / 인프라 재구성

- `tmk-core`를 현재 문서 기준으로 재구현했다.
- 일반 사용자/관리자/Topic/문서/개인 문제/공용 문제/시험/모니터링 엔티티를 새 요구사항에 맞게 정리했다.
- 기존 이메일 인증, 소셜 로그인, 단일 `User`, 단일 `Question` 구조는 제거했다.
- `tmk-infra`의 JPA repository, persistence adapter를 새 포트 구조에 맞게 다시 작성했다.

### 관리자 로그인 API 추가

- 관리자 로그인용 코어 서비스 `AdminLoginService`를 추가했다.
- `POST /admin/auth/v1/login` 엔드포인트를 추가했다.
- 관리자 로그인 시 JWT access/refresh token 발급과 Redis refresh token 저장 흐름을 연결했다.
- JWT claim 구조를 `principalId`, `principalType`, `role` 기준으로 정리했다.

### 개발 기록 방식 정리

- 커밋 시점의 실제 작업만 기록하는 `개발 로그` 문서를 추가했다.
- `commit` 스킬이 커밋 전에 `개발 로그`를 같이 갱신하도록 규칙을 추가했다.

### 관리자 로그인 인증 흐름 정리

- 관리자 로그인을 DB 직접 조회 방식이 아니라 Spring Security `AuthenticationManager` 기반 인증 흐름으로 변경했다.
- `AdminUserDetailsService`를 추가해 관리자 계정을 `UserDetailsService`로 로드하도록 바꿨다.
- 관리자 로그인 컨트롤러에 `ControllerDocs` 인터페이스 패턴을 적용하고 Swagger 어노테이션을 인터페이스로 분리했다.
- 작업 중 비어 있는 패키지 디렉터리와 중복 getter 같은 불필요 코드를 함께 정리했다.

## 2026-04-29

### 관리자 계정 관리 API 추가

- 관리자 계정 목록 조회, 생성, 상태 변경, 삭제 API를 `admin/account` 패키지 구조로 추가했다.
- 관리자 계정 생성 시 현재 로그인한 관리자의 `principalId`를 `createdByAdminId`로 저장하도록 연결했다.
- 관리자 계정 상태 변경과 삭제 시 존재 여부를 검증하고 `ADMIN_NOT_FOUND` 예외를 반환하도록 정리했다.

### 관리자 인증 principal 구조 정리

- `CustomUserDetails`를 `AuthenticatedPrincipal`로 변경해 관리자와 일반 사용자에 공통으로 쓸 수 있는 인증 주체 모델로 정리했다.
- `AdminUserDetailsService`를 `AdminAccountDetailsService`로 변경해 관리자 계정 로더 역할이 드러나도록 맞췄다.
- `/admin/**` 요청에서는 JWT의 `principalType`이 `ADMIN`인지 추가로 검증하도록 필터를 보강했다.

### 커밋 스킬 메시지 규칙 보강

- `commit` 스킬 본문 bullet을 `추가`, `연결`, `보강`, `정리` 같은 동작형 표현으로 작성하도록 규칙을 보강했다.
- `했다` 같은 서술형 과거 표현을 커밋 메시지 본문에서 사용하지 않도록 기준을 추가했다.

## 2026-05-04

### 관리자 Topic / 공용 문제 API 추가

- 관리자 Topic 생성, 삭제 API를 추가했다.
- 관리자 페이지 연동을 위해 Topic 목록 조회 API를 추가하고 응답에 `active`, `questionCount`를 포함하도록 보강했다.
- 관리자 공용 문제 목록, 상세, 등록, 상태 변경, 삭제 API를 추가했다.
- 공용 문제 관련 요청, 결과, 응답, 서비스, 유스케이스, 테스트 구조를 함께 정리했다.

### 공용 문제 조회 쿼리 개선

- 공용 문제 목록 조회를 전체 조회 후 메모리 필터링 방식에서 QueryDSL 기반 조건 조회로 변경했다.
- `topicId`, `difficulty`, `type`, `active` 조건을 DB 쿼리에서 처리하도록 `PublicQuestionPort.search(...)`를 추가했다.
- Topic 이름을 조인 조회하도록 인프라 어댑터를 보강하고 조회 전용 결과 모델을 추가했다.

### 관리자 API 레이어 구조 정리

- 관리자 로그인, 관리자 계정, Topic, 공용 문제 API를 `Service -> Result -> UseCase -> Response` 패턴으로 정리했다.
- UseCase가 요청 DTO를 직접 받아 컨트롤러 파라미터 전개를 줄이도록 맞췄다.
- 응답 변환과 결과 변환 책임을 `Response.from(...)`, `Result.from(...)` 정적 메서드로 모았다.

### 인증 / 트랜잭션 / 개발 규칙 정리

- JWT 필터는 인증 정보 복원만 담당하도록 정리하고 관리자 인가는 Spring Security 설정으로 일원화했다.
- 인증 principal에 관리자와 사용자 역할/타입 상수를 추가해 추후 사용자 인증 확장을 위한 기반을 맞췄다.
- UseCase와 Service의 트랜잭션 표기 기준, 스트림 사용 기준, 레이어 변환 기준을 개발 규칙 문서에 추가하고 관련 코드를 같은 기준으로 정리했다.

## 2026-05-09

### 운영 Caddy 배포 구성 추가

- 운영 Compose에 Caddy 서비스를 추가하고 80/443 포트, Caddy 설정 파일, 사용자/관리자 정적 웹 디렉터리 마운트를 연결했다.
- DuckDNS 사용자/관리자 도메인 기준으로 정적 프론트 서빙과 API 경로 reverse proxy를 분리한 Caddyfile을 추가했다.
- 운영 배포 workflow가 Caddyfile과 두 프론트 정적 파일을 Vultr 배포 경로에 함께 업로드하고 Caddy 컨테이너를 배포 대상으로 포함하도록 조정했다.

### 운영 로그와 배치 주기 조정

- 공통 예외 핸들러와 JWT 인증 필터에서 실제 exception stack trace가 콘솔 로그에 출력되도록 보강했다.
- 시험 자동 제출 배치 실행 주기를 1초에서 1분으로 조정해 사이드 프로젝트 운영 환경의 반복 실행 부담을 낮췄다.
- 운영 배포 workflow에서 API/BATCH 컨테이너만 중지, 삭제, pull 대상으로 유지하고 Caddy는 compose up 단계에서 유지되도록 정리했다.

### 사용자 랜딩 통계 API 정리

- 랜딩 통계 API 패키지를 사용자 영역인 `com.tmk.api.user.landing` 하위로 이동했다.
- 랜딩 통계 조회 경로를 `/api/landing/stats`로 변경하고 사용자 프론트 호출 경로와 보안 허용 경로를 함께 맞췄다.

### 사용자 API 경로 prefix 정리

- 사용자 Topic, 문서, 시험 API 경로를 `/api` prefix 하위로 통일해 Caddy의 사용자 도메인 reverse proxy 규칙과 맞췄다.
- 사용자 웹의 Topic, 문서 업로드/상태/SSE, 시험 생성/시작/응시/결과 호출 경로를 변경된 API 경로로 갱신했다.
- README와 API/TMK/사용자 웹 문서의 사용자 API 경로 예시를 현재 경로에 맞게 수정했다.

### 운영 컨테이너 실행 권한 단순화

- 사이드 프로젝트 운영 편의성을 우선해 API/BATCH 런타임 이미지의 별도 `appuser` 실행 구성을 제거했다.
- 문서 업로드 볼륨 권한 문제를 피하도록 컨테이너 기본 사용자로 실행되게 Dockerfile을 단순화했다.

### 문서 문제 생성 비동기 시작 시점 보정

- 문서 업로드 트랜잭션 커밋 전 비동기 문제 생성이 먼저 실행되어 문서 조회가 실패하던 흐름을 `DocumentUploadedEvent` 기반으로 정리했다.
- `@TransactionalEventListener(AFTER_COMMIT)` 이벤트 핸들러에서 문제 생성을 시작하도록 변경해 커밋된 문서만 비동기 작업에서 조회하도록 보장했다.
- 장애 처리 로그 문서를 추가하고 문서 업로드 후 문제 생성 실패 원인과 처리 시나리오를 기록했다.
