## 프레임워크 선택 이유

### Spring Boot 3.5.11

비교 옵션: Quarkus, Micronaut, Play Framework

| 항목 | Spring Boot | Quarkus | Micronaut |
|------|-------------|---------|-----------|
| 생산성 | ✅ 최고 | 보통 | 보통 |
| 생태계 | ✅ 최대 | 중간 | 작음 |
| 메모리 | 보통 | ✅ 낮음 | ✅ 낮음 |
| 한국 커뮤니티 | ✅ 최대 | 소수 | 소수 |
| LTS 지원 | ✅ 2026년까지 | - | - |

**선택 결정**: 개발 속도와 생태계 우선 (메모리 오버헤드는 수용 가능)

### PostgreSQL + pgvector

비교 옵션: MySQL, Pinecone, Elasticsearch

| 항목 | PostgreSQL+pgvector | Pinecone | Elasticsearch |
|------|---------------------|----------|---------------|
| 월간 비용 | $0~100 (자체 호스팅) | $100+ | $500+ |
| 트랜잭션 지원 | ✅ ACID | ❌ | 제한적 |
| 벡터 검색 성능 | 우수 (HNSW) | 최고 | 우수 |
| 관계형 데이터 통합 | ✅ | ❌ | 제한적 |
| 자체 호스팅 | ✅ | ❌ | ✅ |

**선택 결정**: 관계형(사용자, 시험) + 벡터(임베딩) 통합 관리, MVP 비용 최소화

### JWT 인증

비교 옵션: OAuth 2.0 Session, API Key

| 항목 | JWT | Session |
|------|-----|---------|
| 무상태 | ✅ | ❌ |
| 수평 확장 | ✅ | 복잡 |
| 모바일 친화 | ✅ | 보통 |

**토큰 전략**:
- **AccessToken**: 30분 유효, 요청 헤더 포함
- **RefreshToken**: 7일 유효, Redis 저장

## Redis 캐시 설계

### 키 전략 및 TTL

| 용도 | 키 패턴 | TTL |
|------|---------|-----|
| 사용자 RefreshToken | `refresh_token:USER:{userId}` | 7일 |
| 관리자 RefreshToken | `refresh_token:ADMIN:{adminId}` | 7일 |
| AccessToken 블랙리스트 | `token_blacklist:{accessToken}` | access token 남은 만료 시간 |

## pgvector 설정

```sql
-- pgvector 확장 활성화 (최초 1회)
CREATE EXTENSION IF NOT EXISTS vector;

-- HNSW 인덱스 (코사인 유사도 ANN 검색)
CREATE INDEX idx_document_chunk_embedding_hnsw ON document_chunk
    USING hnsw (embedding vector_cosine_ops)
    WITH (m = 16, ef_construction = 64);
```

| 파라미터 | 값 | 의미 |
|----------|-----|------|
| `m` | 16 | 각 노드의 연결 수 (높을수록 정확, 메모리 증가) |
| `ef_construction` | 64 | 인덱스 빌드 시 탐색 범위 (높을수록 정확, 빌드 느림) |

### PostgreSQL 초기 설정

사용할 데이터베이스 이름과 계정은 운영 환경에 맞게 직접 생성하고, 해당 데이터베이스에서 `pgvector` 확장을 활성화해야 합니다.

```sql
CREATE EXTENSION IF NOT EXISTS vector;
```

### 빌드 및 실행

```bash
# 전체 빌드
./gradlew build

# API 서버 실행
SPRING_PROFILES_ACTIVE=dev ./gradlew :tmk-api:bootRun

# 전체 테스트
./gradlew test

# 특정 테스트 클래스 실행
./gradlew test --tests "com.tmk.api.SomeTest"

# 빌드 캐시 무시하고 테스트
./gradlew test --rerun-tasks

# Batch 서버 실행
SPRING_PROFILES_ACTIVE=dev ./gradlew :tmk-batch:bootRun
```

## 모듈별 의존성 구조

```
tmk-api (bootJar)
  ├── tmk-core
  ├── tmk-infra
  ├── spring-boot-starter-web
  ├── spring-boot-starter-security
  ├── spring-boot-starter-data-jpa
  ├── spring-boot-starter-data-redis
  ├── spring-boot-starter-mail
  ├── spring-boot-starter-validation
  ├── springdoc-openapi-starter-webmvc-ui
  ├── openai-java
  ├── pdfbox
  └── jjwt (0.12.6)

tmk-infra (jar)
  ├── tmk-core
  ├── spring-data-jpa
  └── postgresql

tmk-core (jar)
  ├── flyway-core
  ├── flyway-database-postgresql
  ├── spring-boot-starter-data-jpa
  ├── hibernate-vector
  └── postgresql (JDBC driver)

tmk-batch (bootJar)
  ├── tmk-core
  ├── tmk-infra
  └── spring-boot-starter-batch
```

> 의존성 방향: `tmk-api` → `tmk-core`, `tmk-infra` / `tmk-batch` → `tmk-core`, `tmk-infra`
> `tmk-core`는 외부 프레임워크에 의존하지 않는 순수 도메인 모듈
